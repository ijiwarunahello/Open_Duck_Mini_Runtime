# Bench GUI (モジュール別の動作確認ツール) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pi 上で動く Web サーバとブラウザ画面で、Open Duck Mini の各モジュール (GPIO・足・IMU・LED・耳・スピーカー・カメラ・サーボ) の生の値を見ながら操作できる計測器を作る。

**Architecture:** `tools/bench/` に標準ライブラリの `ThreadingHTTPServer` と Server-Sent Events のサーバを置き、ハードウェアは `Hardware` プロトコルの実装 (`RealHardware` / `FakeHardware`) 越しに触る。判断の入る処理 (ピン表、pinctrl の読み取り、サーボの安全制限、チャタリング、座標変換) は純粋な関数・クラスに分けて単体テストする。画面はビルドなしの HTML/CSS/JS 3 ファイル。

**Tech Stack:** Python 3.12 (uv)、標準ライブラリ (http.server, threading, subprocess, wave)、RPi.GPIO 0.7.1、adafruit-circuitpython-bno055 (Blinka)、pypot `FeetechSTS3215IO`、外部コマンド `pinctrl` / `aplay` / `rpicam-still` / `vcgencmd`、pytest。

**Spec:** ducktronics-hub `docs/plans/20261122-bench-gui.md` (hub PR #8)

## Global Constraints

- Python 3.12 の Runtime venv で動かす (`uv run`)。onnxruntime 1.18.1 のため 3.13 にしない。
- 追加の Web フレームワークを入れない。外部 CDN を読み込まない。
- `tools/bench` のモジュールは、import 時にハードウェアのライブラリ (RPi.GPIO, board, pypot) を読み込まない。`RealHardware` の中で遅延 import する (PC でテストを動かすため)。
- サーボは pypot `FeetechSTS3215IO("/dev/ttyACM0", baudrate=1000000, use_sync_read=True)` だけで扱う (rustypot と同時に同じポートを開かない)。pypot の位置は度。画面とログは rad に直す。
- 汎用の GPIO 操作はプルの切り替え (pu / pd / pn) だけ。出力は出さない。予約 {0, 1, 4, 14, 15} と使用中 {2, 3, 12, 13, 18, 19, 20, 21, 22, 23, 24, 25, 27} のピンは汎用操作の対象外。
- サーボ: kp は 2 / 8 / 16 から選ぶ。1 回の移動 ±0.05 rad。累計はトルクを入れた時点の位置から ±0.3 rad。トルクは同時に 1 軸だけ。
- LED は点灯から 30 秒で自動消灯。耳の範囲は既定 ±0.5、`--ear-limit` で最大 1.0。
- 「すべて止める」: 全サーボのトルク OFF、LED 消灯、耳の PWM 停止。ボタン、最後のブラウザ接続の切断、サーバ終了 (Ctrl-C を含む) で実行する。
- 歩行 Runtime などが動いていれば起動しない。サーボのポートは TIOCEXCL で排他にする。
- 画面の文言は日本語。

## Review Focus

1. 2 つのブラウザで開いていて片方を閉じた → 停止処理は走らない。両方閉じたときだけ走る (Task 6 `test_stop_all_only_after_last_client`)。
2. サーボの USB が途中で抜けた / 読み取りが失敗した → サーバは落ちず、サーボ表に「読み取りエラー」と出て、次の周期で読み直す (Task 6 `test_servo_read_error_does_not_crash_stream`)。
3. IMU の読み取りが例外を出した → エラー回数が増えるだけで、値の配信は続く (Task 6 `test_imu_error_counted`)。
4. 移動ボタンの連打で ±0.3 rad を超えようとした → 超える移動は拒否し、理由を返す (Task 2 `test_jog_refuses_beyond_travel_limit`)。
5. 使用中・予約のピンに対するプル変更の要求 (画面を経由しない直接の POST を含む) → 400 で拒否 (Task 6 `test_set_pull_rejects_reserved_pin`)。
